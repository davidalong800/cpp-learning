## 1. 🔴 Чтение строки с пробелами: `std::getline` — умею

```cpp
std::string name;
std::getline(std::cin, name);   // читает ВСЮ строку до Enter
```

🔴 Я знаю, что:

- синтаксис ровно такой: `std::getline(std::cin, имя_переменной);` — поток, потом переменная;
- `getline` читает всю строку до нажатия Enter, включая пробелы;
- символ `\n` в саму строку НЕ попадает — он «съедается» и становится концом строки.

🔴 Отличие от `cin >>`:

| Что пишу | Что прочитается из строки `Давид Кузнецов` |
|---|---|
| `std::cin >> name` | `Давид` — только до первого пробела |
| `std::getline(std::cin, name)` | `Давид Кузнецов` — вся строка целиком |

🟡 Я понимаю, что `cin >>` останавливается на пробеле, а `getline` — только на Enter.

## 2. 🔴 Ловушка буфера — знаю и обхожу

```cpp
int age;
std::cin >> age;                  // прочитал число, а '\n' остался в буфере
std::cin.ignore(10000, '\n');     // лекарство: выбросить остаток строки
std::getline(std::cin, name);     // теперь читается настоящее имя
```

🔴 Я знаю, что:

- после `cin >> x` в буфере остаётся `\n`, который я не нажимал «лишний раз»;
- `getline` первым делом встречает этот `\n` и возвращает ПУСТУЮ строку;
- лекарство — `std::cin.ignore(10000, '\n');` между `cin >>` и `getline`.

🟡 Я понимаю, что `std::cin.ignore();` без аргументов выбросит только один символ, и это работает не всегда надёжно, поэтому пишу полную форму `ignore(10000, '\n')` — «выбрось до 10000 символов или до конца строки».

🟡 Я понимаю, что если программа сначала спрашивает имя, а потом возраст, то ловушки нет: `getline` идёт первым и пустой строки не будет.

## 3. 🔴 Условия `if` / `else` — знаю наизусть

```cpp
// форма 1: только если
if (x > 0) {
    std::cout << "Положительное\n";
}

// форма 2: если / иначе
if (x > 0) {
    std::cout << "Положительное\n";
} else {
    std::cout << "Не положительное\n";
}

// форма 3: цепочка
if (x > 0) {
    std::cout << "Положительное\n";
} else if (x < 0) {
    std::cout << "Отрицательное\n";
} else {
    std::cout << "Ноль\n";
}
```

🔴 Я знаю, что:

- условие всегда в круглых скобках `( )`, тело — в фигурных `{ }`;
- после `if (...)` точка с запятой НЕ ставится;
- `else` не может стоять без своего `if`;
- проверки идут сверху вниз, срабатывает ПЕРВАЯ подходящая, остальные пропускаются;
- тело всегда пишу в `{ }`, даже если там одна команда — так не будет ошибок при доработке.

🔴 Я знаю главную ловушку: `=` — это присваивание, а `==` — сравнение.

```cpp
if (x = 5) { }     // ОШИБКА: положил 5 в x, а не сравнил
if (x == 5) { }    // правильно: сравнил
```

## 4. 🔴 Логические операторы — знаю

| Оператор | Читается | Пример | Результат |
|---|---|---|---|
| `==` | равно | `x == 5` | истина, если x равно 5 |
| `!=` | не равно | `x != 5` | истина, если x не равно 5 |
| `<` | меньше | `x < 5` | |
| `>` | больше | `x > 5` | |
| `<=` | меньше или равно | `x <= 5` | |
| `>=` | больше или равно | `x >= 5` | |
| `&&` | И | `a > 0 && b > 0` | истина, когда ИСТИННЫ ОБА |
| \|\| | ИЛИ | a > 0 \|\| b > 0 | истина, когда истинно ХОТЯ БЫ ОДНО |
| `!` | НЕ | `!(x > 0)` | переворачивает: было true — стало false |

🔴 Таблицы истинности — знаю наизусть:

| `a` | `b` | `a && b` | a \|\| b |
|---|---|---|---|
| true | true | true | true |
| true | false | false | true |
| false | true | false | true |
| false | false | false | false |

🟡 Я вижу закономерность: `&&` выдаёт true только в одной строке из четырёх, а `||` — false только в одной.

## 5. 🔴 Типичные ошибки с логикой — знаю и не допускаю

1. Двойное сравнение — самая коварная ошибка:

```cpp
if (18 <= age <= 65) { }        // ОШИБКА: всегда true, так писать нельзя
if (age >= 18 && age <= 65) { } // правильно: два сравнения и &&
```

   🟡 Я понимаю, почему это так: сначала вычисляется `18 <= age` и даёт `true` или `false`, то есть `0` или `1`, а потом это число сравнивается с `65` — и оно всегда меньше. Поэтому условие всегда истинно.

2. Забыть скобки перед `||`:

```cpp
if (a >= 10 && a <= 20 || a == 100) { }        // читается не так, как кажется
if ((a >= 10 && a <= 20) || a == 100) { }      // правильно: скобки расставляют смысл
```

3. `!` без скобок: `!x > 0` — это `(!x) > 0`, а не «не (x > 0)». Пишу `!(x > 0)`.

## 6. 🔴 Приоритет операторов — знаю

От высшего к низшему:

```
1. * / %              (умножение, деление, остаток)
2. + -                (сложение, вычитание)
3. < > <= >=          (сравнения)
4. == !=              (равенство)
5. &&                 (И)
6. ||                 (ИЛИ)
```

🔴 Я знаю этот порядок наизусть и проверяю по нему любое составное условие:

- раньше всех считаются `* / %`, потом `+ -`;
- сравнения ` < > <= >= ` идут после арифметики, поэтому `a + 1 < b * 2` читается как `(a + 1) < (b * 2)`;
- `==` и `!=` слабее сравнений, поэтому `x < 5 == true` — плохая запись, пишу скобки;
- `&&` сильнее `||`, и это последнее, что меня путает.

🔴 Практический вывод: `&&` связывает сильнее, чем `||`, поэтому смешанное условие я всегда разбиваю скобками — так код читается с первого взгляда, без сверки с таблицей.

🟡 Проверяю себя на примере: `x > 0 && x < 10 || x == 100` вычисляется как `(x > 0 && x < 10) || (x == 100)`, но записываю я это со скобками — явно.

🟡 Скобки `( )` стоят выше всего списка: что в скобках — считается первым, и это мой главный инструмент, когда порядок неочевиден.

🟡 `!` (НЕ) — унарный оператор, он прилипает к ближайшему значению сильнее любого оператора из списка: `!x > 0` — это `(!x) > 0`, а не `!(x > 0)`.

🟡 Короткое замыкание — понимаю:

- в `a && b` при `a == false` правая часть НЕ вычисляется, сразу `false`;
- в `a || b` при `a == true` правая часть НЕ вычисляется, сразу `true`.

🟡 Я понимаю, что это не мелочь: так программа не делает лишней работы, и на этом строится защита проверок.

## 7. 🔴 Остаток от деления `%` — умею

```cpp
7 % 2    // 1
8 % 2    // 0
10 % 3   // 1
```

🔴 Проверка чётности — пишу по памяти:

```cpp
if (number % 2 == 0) {
    std::cout << "Чётное\n";
} else {
    std::cout << "Нечётное\n";
}
```

🔴 Я знаю, что:

- `%` даёт остаток от деления, а не дробную часть: `10 % 3` — это `1`;
- `%` работает только с целыми числами (`int`), с `double` — ошибка компиляции;
- `% 2 == 0` — чётное, значит `% 2 == 1` — нечётное;
- `0` — чётное число, потому что `0 % 2 == 0`;
- для отрицательных проверка тоже работает: `-7 % 2` даёт `-1`, то есть не `0`, и число честно считается нечётным;
- делить на ноль нельзя: `7 % 0` — ошибка во время работы программы.
